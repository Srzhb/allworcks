# SOC Analyst — учебное портфолио

Четыре работающих учебных проекта по направлениям из резюме Junior SOC Analyst:
мониторинг событий, анализ сетевого трафика, исследование фишинга и threat hunting в Windows.

Это новые демонстрационные реализации по описаниям из резюме. Все входные данные
синтетические; отчёты показывают результаты локальных примеров, а не расследования
реальных инцидентов или результаты работы в компании.

| Проект | Что можно попробовать | Материалы для лаборатории |
| --- | --- | --- |
| [Мониторинг SIEM](projects/siem-monitoring/) | Подбор паролей, PowerShell, пороги и исключения | Wazuh, Windows, Linux, Sysmon |
| [Анализ сети](projects/network-analysis/) | Разбор PCAP, DNS/HTTP, сканирование портов, IOC | Wireshark, Suricata, Zeek |
| [Фишинг и IOC](projects/phishing-ioc/) | Разбор EML, заголовки, ссылки, репутация индикаторов | VirusTotal и AlienVault OTX: offline-фикстуры и опциональные API |
| [Windows threat hunting](projects/windows-threat-hunting/) | Процессы, сетевые соединения, временная шкала | Sigma, Sysmon, MITRE ATT&CK |

## Быстрый запуск

Для основных анализаторов достаточно **Python 3.11+** и стандартной библиотеки.
Wazuh, Suricata, Zeek и API-ключи для демонстрации не нужны.

```bash
git clone https://github.com/Srzhb/allworcks.git
cd allworcks
python scripts/demo.py
python scripts/test.py
```

В системах, где Python доступен как `python3`, замените `python` на `python3`.
Демонстрация создаёт JSON-отчёты и CSV с временной шкалой в `reports/`.
Повторный запуск перезаписывает эти отчёты. Другая папка:

```bash
python scripts/demo.py --output-dir /tmp/soc-reports
```

Каждый проект запускается независимо; точные команды, схема входных данных,
примеры результатов и ограничения описаны в его README.

Необязательная проверка синтаксиса Sigma через pySigma и корректности XML:

```bash
python -m pip install -r requirements-dev.txt
python scripts/validate_rules.py
```

Эта проверка не запускает движки Wazuh или Sigma backend.

## Как проверять результаты

1. Запустите все примеры и тесты командами выше.
2. Сопоставьте находки с входными событиями: время, адрес, процесс, идентификатор пакета.
3. Посмотрите отрицательные сценарии в тестах: обычная активность не должна давать те же находки.
4. Для проверки в настоящей SIEM/IDS используйте конфигурации и инструкции соответствующего проекта.

Локальные Python-анализаторы и правила внешних систем имеют разные возможности.
Установка конфигурации и проверка правила в Wazuh, Suricata, Zeek или конкретном
Sigma backend выполняются отдельно. Ни один эвристический сигнал сам по себе
не доказывает компрометацию.

## Работа с собственными данными

Ключи Threat Intelligence задаются через переменные окружения; пример —
[.env.example](.env.example). Сам файл `.env` автоматически не загружается.
Сетевые запросы в проекте фишинга включаются только параметром `--online`.
Содержимое писем и вложений в API не отправляется; сведения об IOC при online-проверке
передаются выбранным сервисам.

Реальные журналы, письма, дампы, секреты и отчёты с ними храните вне репозитория.
Каталог `reports/` исключён из Git. Контактные данные и исходный PDF резюме
в этот репозиторий не включены.
