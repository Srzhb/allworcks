# Разбор подозрительного письма

Небольшой скрипт на Python для разбора `.eml` и поиска индикаторов.
Это учебная реализация по темам из резюме, без кода и данных работодателей.
Нужен Python 3.11 или новее. Дополнительных библиотек нет.

Команды выполняются из корня репозитория:

```bash
python projects/phishing-ioc/run.py \
  --input projects/phishing-ioc/data/suspicious.eml \
  --output reports/phishing.json
```

В JSON попадут адреса From/Reply-To, результаты из заголовков и найденные IOC:
ссылки, домены, IPv4/IPv6 и строки MD5/SHA-1/SHA-256.
Скрипт отмечает различие From/Reply-To, HTTP-ссылки и ссылки с IP вместо домена.
Ссылки обезврежены: `https://example.test` → `hxxps://example[.]test`.
Без `--output` результат печатается в терминал.

`data/suspicious.eml` и `data/ti-fixtures.json` — выдуманные примеры.
Совпадение с этой базой не является настоящим результатом VirusTotal или OTX.
Отсутствие совпадения тоже не означает, что индикатор безопасен.
Другую тестовую базу можно указать через `--fixtures путь/к/базе.json`.

По умолчанию всё работает локально. Для запросов к API нужен `--online`
и переменные окружения `VT_API_KEY` и/или `OTX_API_KEY` с вашими ключами:

```bash
python projects/phishing-ioc/run.py --input /path/to/message.eml --online
```

Отправляются только извлечённые публичные домены, IP и строки хешей.
Письмо, заголовки, вложения и полные URL остаются локально.
Частные IP и известные специальные домены (`.test`, `.internal`, `.onion` и другие) пропускаются.
Неизвестное внутреннее имя домена скрипт может не распознать — учитывайте это перед запросом.
Лимит — 20 индикаторов на сервис, таймаут — 5 секунд; есть `--max-lookups` и `--timeout`.
При 429/401/403 сервис отключается до конца запуска. Тесты API используют mock, живые сервисы не вызывались.

`Authentication-Results` имеет статус `REPORTED`: заголовок можно подделать.
Скрипт не проверяет SPF, DKIM и DMARC; для этого нужна проверка на доверенном почтовом шлюзе.
Вложения и вложенные письма не анализируются. Максимальный размер входа — 10 MiB.
Отчёт может содержать личные данные и токены в URL: обезвреживание не анонимизирует их.
`analysis.py` разбирает письмо, `intelligence.py` работает с TI, `run.py` запускает обработку.

```bash
python -m unittest discover -s projects/phishing-ioc/tests -v
```
