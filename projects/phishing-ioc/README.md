# Phishing IOC Lab

Учебный проект на Python 3.11+ для первичного разбора писем `.eml`: заголовки, ссылки, домены, IP-адреса, строки хешей и контекст threat intelligence. Идея основана на компетенциях из резюме — анализ фишинга, SPF/DKIM/DMARC, VirusTotal и AlienVault OTX. Это самостоятельная реализация для портфолио, а не исходный код, данные или внутренние правила работодателя.

Зависимости: только стандартная библиотека Python. Установка пакетов и Docker не нужны. Команды ниже выполняются из корня репозитория.

## Быстрый запуск

```bash
python projects/phishing-ioc/run.py \
  --input projects/phishing-ioc/data/suspicious.eml \
  --output reports/phishing.json
```

Результат — JSON в `reports/phishing.json`. Если убрать `--output`, отчёт выводится в терминал. Отчёт содержит:

- Отправителя, Reply-To, тему и количество пропущенных вложений.
- Заголовки `Authentication-Results` со статусом `REPORTED`.
- Сигналы для проверки: различающиеся From/Reply-To, заявленная ошибка SPF/DKIM/DMARC, HTTP-ссылка, ссылка с IP вместо домена.
- Дедуплицированные URL, домены, IPv4/IPv6, MD5/SHA-1/SHA-256 строки.
- Совпадения с демонстрационной TI-базой; отсутствие записи означает `no_fixture`, а не безопасный объект.

Ссылки и адреса в отчёте обезврежены: `https://login.example.test` превращается в `hxxps://login[.]example[.]test`, email — в `user[@]example[.]test`. Исходное письмо не изменяется. Из HTML извлекаются ссылки и текст; HTML не исполняется, адреса не открываются.

Пример части результата:

```json
{
  "type": "domain",
  "indicator": "login[.]example[.]test",
  "offline": {
    "source": "synthetic_fixture",
    "status": "demo_match",
    "label": "simulated_suspicious",
    "note": "Invented training label for the demo login domain."
  }
}
```

`data/suspicious.eml` полностью выдуман: зарезервированные `.test` / `example.org`, адреса `192.0.2.0/24` и `2001:db8::/32`, повторяющаяся строка SHA-256. `data/ti-fixtures.json` не содержит выгрузку VirusTotal/OTX; её метки придуманы исключительно для воспроизводимого демо.

Другую синтетическую TI-базу можно передать явно:

```bash
python projects/phishing-ioc/run.py \
  --input projects/phishing-ioc/data/suspicious.eml \
  --fixtures projects/phishing-ioc/data/ti-fixtures.json
```

Формат базы: `{"synthetic": true, "indicators": {"domain:training.example.test": {"label": "training", "note": "Synthetic example"}}}`. Допустимы ключи типов `domain`, `ipv4`, `ipv6`, `hash`, `url`.

## Опциональный доступ к VirusTotal и OTX

По умолчанию программа работает без сети, даже если API-ключи уже заданы. Флаг `--online` включает только GET-запросы существующей информации об извлечённых публичных доменах, IP и строках хешей. Ключи читаются из `VT_API_KEY` и `OTX_API_KEY`; можно настроить любой один сервис. Отсутствующий ключ даёт `skipped`.

В Bash ключи можно ввести без отображения в терминале:

```bash
read -r -s -p 'VirusTotal API key: ' VT_API_KEY
export VT_API_KEY
read -r -s -p 'OTX API key: ' OTX_API_KEY
export OTX_API_KEY
python projects/phishing-ioc/run.py \
  --input /path/to/message.eml \
  --output reports/phishing-online.json \
  --online --max-lookups 20 --timeout 5
unset VT_API_KEY OTX_API_KEY
```

Содержимое письма, заголовки, вложения, байты файлов и полные URL не передаются. URL остаются локально; может проверяться только извлечённый из них публичный домен или IP. Не передаются также private/loopback/documentation/multicast IP и известные зарезервированные домены. Произвольное внутреннее доменное имя по одной строке распознать нельзя: перед включением сети оцените допустимость раскрытия индикаторов внешнему сервису.

Максимум по умолчанию — 20 подходящих индикаторов на провайдера, то есть до 40 HTTP-запросов при двух ключах; `--max-lookups` принимает 1–200. Таймаут одного запроса по умолчанию 5 секунд, допустимо до 30. Автоматических повторов нет. При HTTP 429 дальнейшие запросы к этому провайдеру прекращаются до следующего запуска; аналогично при 401/403. Ошибка сети, отсутствие результата или некорректный ответ отражаются статусом и не превращаются в «чистую» репутацию. Redirect не выполняется, чтобы заголовок с ключом не ушёл другому хосту. Размер ответа API ограничен 1 MiB; тела ошибок и ключи не включаются в отчёт.

Для VirusTotal выводятся только счётчики `last_analysis_stats`; для OTX — число упоминаний в pulses. Упоминание в OTX не является вердиктом о вредоносности, а отсутствие детектов VirusTotal не доказывает безопасность. Данные сервиса могут быть устаревшими. Online-режим требует действующих ключей и соблюдения лимитов вашего тарифа; интеграции в тестах проверяются через mock, реальные запросы при разработке не выполнялись.

## Проверка

```bash
python -m unittest discover -s projects/phishing-ioc/tests -v
```

Тесты проверяют MIME/base64/HTML-разбор, исключение вложений, извлечение и defang IOC, недоверенные authentication-заголовки, отсутствие сети в offline-режиме, лимит запросов, мокированные ответы обоих API, 401/403/404/429/503, таймауты, некорректный/слишком большой JSON и отсутствие ключей/тел API-ошибок в результатах.

## Границы применимости

- `Authentication-Results` — утверждение внутри EML, которое можно подделать. Статус `REPORTED` не подтверждает SPF, DKIM или DMARC. Для проверки нужны принимающий почтовый шлюз, доверенная граница заголовков и соответствующая DNS/криптографическая проверка. Здесь они не выполняются.
- Различающийся Reply-To и HTTP-ссылка — повод изучить письмо; нормальные рассылки тоже могут иметь эти признаки. Итогового вердикта «фишинг/безопасно» программа не выносит.
- DNS, WHOIS, редиректы ссылок и загрузка страниц не выполняются. Public Suffix List и анализ похожих Unicode-доменов не используются. Извлечение regex может включить строку, похожую на домен, и пропустить нестандартную обфускацию.
- Поддержаны обычные MIME-текст и HTML. Зашифрованные части, архивы, вложенные письма и вложения не анализируются; хеши извлекаются из текста, содержимое вложений не хешируется. Есть предел 10 MiB на входной файл.
- Отчёт сохраняется локально и может содержать тему письма, адреса и токены в обезвреженных URL. Defang убирает активность ссылки, но не анонимизирует её. Для публикации используйте синтетические письма из `data/`.

Код: `analysis.py` отвечает за MIME и IOC; `intelligence.py` — за локальные фикстуры и ограниченные GET-запросы; `cli.py` — за явный выбор режима и JSON-отчёт.
