# Windows Threat Hunting Lab

Учебный офлайн анализ Sysmon: общая временная шкала запуска процессов и сетевых
соединений, три объяснимые эвристики, корреляция по `Computer + ProcessGuid`,
JSON отчёт и необязательный CSV. Реализация на Python 3.11+, только стандартная
библиотека. Установка пакетов, Windows и права администратора не нужны.

Это воспроизводимый лабораторный проект по теме Windows Event Log, Sysmon,
Sigma и MITRE ATT&CK. Он не подтверждает опыт промышленной эксплуатации.
Все события в `data/` синтетические: компьютеры LAB, вымышленные GUID,
документационные IP из TEST-NET. Содержимое команд — строки для анализа;
программа ничего не запускает, не декодирует и не отправляет по сети.

## Запуск из корня репозитория

```sh
python projects/windows-threat-hunting/run.py --input projects/windows-threat-hunting/data/events.jsonl --output reports/windows.json --timeline-csv reports/windows-timeline.csv
python projects/windows-threat-hunting/run.py --input projects/windows-threat-hunting/data/sysmon.xml --output reports/windows-xml.json
python -m unittest discover -s projects/windows-threat-hunting/tests -v
```

Для JSONL примера ожидаются **12 событий, 3 срабатывания**: по одному WH001,
WH002 и WH003; четыре сетевых события получат контекст запуска процесса.
В XML примере 3 события, 2 срабатывания: WH001 и WH003. `--format jsonl|xml`
переопределяет автоопределение по расширению. Код возврата: `0` — отчёт записан,
`2` — ошибка входного файла, аргументов или записи. Наличие срабатываний не
меняет код возврата: это инструмент анализа, а не блокирующая проверка.

В `summary` находятся счётчики, в `detections` — правило, ATT&CK теги и
конкретные поля доказательств, в `timeline` — все поддержанные события в UTC.
`timeline_sequence` связывает срабатывание со строкой шкалы. CSV предназначен
для просмотра; строки, начинающиеся с формульных символов, экранируются
апострофом. Исходные значения сохраняются в JSON.

## Правила и условия

| ID | Условие | Контекст ATT&CK |
| --- | --- | --- |
| WH001 | Sysmon 1; powershell.exe/pwsh.exe; `-e`, `-ec`, `-enc` или `-encodedcommand` и base64-подобный аргумент длиной от 8 символов | T1059.001 |
| WH002 | Sysmon 1; WINWORD/EXCEL/POWERPNT/OUTLOOK запускает PowerShell, cmd, wscript или cscript | T1204.002, T1059 |
| WH003 | Sysmon 3; PowerShell/wscript/cscript соединяется на порт 1337, 4444 или 9001; точные адреса 127.0.0.1 и ::1 исключены | T1059; гипотеза Command and Control |

ATT&CK теги задают направление расследования, а не доказательство техники.
Порты WH003 — маленький демонстрационный список, не источник threat intelligence.
WH003 не определяет публичность адреса или сетевой протокол приложения.
Другие loopback адреса из `127.0.0.0/8` не исключены: фильтр точно соответствует
двум значениям в Sigma. Тесты проверяют положительные и отрицательные примеры,
включая обычный PowerShell, разрешённого потомка Office, браузер на 4444,
PowerShell на 443 и явный loopback.

## Входные данные и сопоставление полей

JSONL: один объект на строку. Обязательны `timestamp` с часовым поясом,
`event_id` и `computer`; для Event 1 нужен `image`, для Event 3 —
`destination_ip` и `destination_port`. `process_guid` может отсутствовать,
тогда соединение не коррелируется; `image` в Event 3 может быть восстановлен
по GUID. Пример:

```json
{"timestamp":"2026-01-15T10:00:00Z","event_id":1,"computer":"LAB-WIN11","process_guid":"{11111111-1111-4111-8111-111111111111}","image":"C:\\Windows\\System32\\WindowsPowerShell\\v1.0\\powershell.exe","command_line":"powershell.exe -NoProfile -File C:\\Lab\\inventory.ps1","parent_image":"C:\\Windows\\explorer.exe"}
```

| JSONL | Sysmon XML / поле Sigma | Обработка |
| --- | --- | --- |
| `timestamp` | `System/TimeCreated/@SystemTime` или `UtcTime` | UTC, сортировка по полному времени; `UtcTime` без пояса считается UTC |
| `event_id` | `System/EventID` / `EventID` | Только 1 и 3, остальные пропускаются |
| `computer` | `System/Computer` / `Computer` | Обязателен; корреляция без учёта регистра |
| `process_guid` | `ProcessGuid` | Без фигурных скобок, в нижнем регистре |
| `process_id` | `ProcessId` | Необязательный PID; не используется как ключ |
| `image` | `Image` | `/` заменяется на `\`; сравнение имени без учёта регистра |
| `command_line` | `CommandLine` | Строка, без исполнения и полного разбора синтаксиса PowerShell |
| `parent_image` | `ParentImage` | Та же нормализация пути, что у Image |
| `destination_ip` | `DestinationIp` | Проверка IPv4/IPv6 и каноническая запись |
| `destination_port` | `DestinationPort` | Целое 0–65535 |
| `protocol` | `Protocol` | Необязательная строка в нижнем регистре |
| `record_id` | `System/EventRecordID` | Необязательный идентификатор для просмотра |

JSONL также принимает имена полей из правого столбца (`UtcTime`, `Image`,
`EventID` и т. д.). JSONL по договорённости содержит нормализованные Sysmon
события; если `provider` указан, допускается `Microsoft-Windows-Sysmon`.
XML принимает отдельный `<Event>` или экспорт `<Events>` с пространством имён
и читает только Provider `Microsoft-Windows-Sysmon`. Это экспорт XML, **не**
бинарный EVTX. DTD/entity объявления запрещены.

Соединение получает контекст последнего предшествующего запуска на том же
компьютере с тем же GUID. При равном времени сначала обрабатывается Event 1.
Событие сети может стоять выше запуска во входном файле: сортировка восстановит
порядок. Более поздний запуск не привязывается к раннему соединению. Нет
корреляции только по PID: это предотвращает ошибки от повторного использования
PID и одинаковых GUID на разных компьютерах. Поля самой сети имеют приоритет
перед полями процесса; `correlated_process_creation` показывает время источника
контекста. Поле `Image` для сетевого Sigma правила надо обогащать тем же способом.

## Sigma и границы проверки

В `sigma/` находятся три **experimental** правила Sigma с теми же условиями.
Python выполняет заранее реализованное подмножество условий этих правил;
это **эталонная оценка подмножества, не полноценный Sigma backend**. YAML не
загружается при запуске и его изменение не меняет Python правила автоматически.
Тесты используют одни и те же фикстуры, сверяют ожидаемые rule ID и проверяют
регулярные выражения/портовые списки из YAML со значениями реализации.
Компиляция pySigma и проверка в SIEM в этот проект не входят. При переносе
нужно настроить logsource, сопоставление полей и обогащение сетевого Image.

Команда PowerShell с кавычками вокруг base64, другие сокращения ключа и
обфускация могут не совпасть с WH001. Легитимное управление, макросы и тестовые
сервисы могут вызвать срабатывания. Нет allowlist, базовой линии организации,
анализа содержимого скриптов, дерева всех предков, live collection, EVTX парсера
или оценки вредоносности. Файл целиком загружается в память; инструмент
предназначен для небольших лабораторных выборок. Исходные реальные журналы
могут содержать секреты в командных строках: для публикации используйте
предоставленные синтетические примеры.
