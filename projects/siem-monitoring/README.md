# Мониторинг событий SIEM

Небольшая учебная работа по задачам SOC из резюме: поиск серий неудачных входов и подозрительных строк PowerShell.
Все 21 событие в примере придуманы. Здесь нет реальных логов, персональных данных и кода работодателя.

Нужен Python 3.11 или новее. Дополнительные библиотеки устанавливать не нужно.
Команда из корня репозитория:

```bash
python projects/siem-monitoring/run.py --input projects/siem-monitoring/data/events.jsonl --output projects/siem-monitoring/examples/report.json
```

В отчете получится 5 оповещений: три серии ошибок входа и два запуска PowerShell для ручной проверки.
Без `--output` результат выводится в терминал. Входной файл нельзя перезаписать отчетом.

Вход — JSONL: один объект на строку. Обязательные поля: `event_key`, `timestamp`, `host`, `account`, `source`, `event_type`.
Время должно содержать часовой пояс, а `event_key` не должен повторяться.
`source`: `windows_security`, `linux_auth` или `sysmon`; тип события: `authentication_failed`, `authentication_success` или `process_start`.
Для запуска процесса также нужны `process_name` и `command_line`. Это учебная схема, не готовый импорт сырых логов Wazuh.
Пример одной строки:

```json
{"event_key":"demo-1","timestamp":"2026-01-15T12:00:00Z","host":"lab-win-01","account":"demo","source":"windows_security","event_type":"authentication_failed","source_ip":"192.0.2.40"}
```

Сначала события сортируются по времени. Ошибки входа считаются отдельно для каждой пары хост/учетная запись.
По умолчанию оповещение появляется при 5 ошибках за 300 секунд, включая границу окна. Плотная серия не дает оповещение на каждую новую ошибку.
Когда старые ошибки выходят из окна и счетчик падает ниже порога, следующая серия может дать новое оповещение.
PowerShell проверяется по `-EncodedCommand` / `-enc` и сочетанию загрузки с выполнением выражения. Команды не исполняются.
Пороги меняются через `--failure-threshold` и `--window-seconds`.
`--allow-source-ip 198.51.100.10` исключит 5 ошибок условного сканера: останется 4 оповещения. На PowerShell исключение не действует.

В `analyzer.py` находится обработка событий, в `run.py` — чтение параметров и запись отчета.
В `data/` лежит пример входа, в `examples/` — готовый отчет, в `tests/` — 19 проверок:

```bash
python -m unittest discover -s projects/siem-monitoring/tests -v
```

В `wazuh/` находятся шаблоны сбора Windows/Sysmon/Linux и правил для Wazuh 4.12.
Windows-правила используют встроенные родители `60122` и `61603`; на другой версии их нужно проверить.
Шаблоны отделены от Python-скрипта: менеджер Wazuh здесь не запускался, срабатывание правил на нем не проверено.

Ограничения: весь вход хранится в памяти; готового подключения к агентам и обработчика сырых логов нет.
Поиск по словам может пропустить обфускацию или ошибиться на комментарии. Кодированная команда сама по себе не доказывает атаку.
Оповещения требуют ручного разбора: ошибки бывают из-за старых паролей служб, а PowerShell используют и администраторы.

Что можно изучить дальше: добавить разбор реального формата в своей лаборатории, проверить шаблоны через `wazuh-logtest`, сравнить ложные срабатывания на размеченных примерах.
